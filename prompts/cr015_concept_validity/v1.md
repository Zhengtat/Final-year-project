    Is this correctly bounded phrase an independently valid technical concept in this context?

A technical concept is a word or short noun phrase that names a knowledge element of the field with a specific meaning in it: a protocol, mechanism,
component, data unit, parameter, property, event, state, layer, identifier, or a general technical idea. A word that is also an everyday word IS a
concept when the field gives it a specific technical meaning here.

Verdicts (exactly one per span):
- ACCEPT_NEW: an independently valid technical concept in this sentence.
- LINK_EXISTING: the same concept as one of the EXISTING MATCHES on its line (use only when a match is listed; give its node_id).
- REJECT_NOT_CONCEPT: not a concept: a descriptive phrase or a wrapper that only adds description to a term that is already named by a shorter span
  listed in the same family, a clause or fragment, a value or quantity, an example object or personal name, a discourse or reference phrase
  ("the following discussion", "second mechanism"), an evaluative phrase.
- REJECT_GENERIC: a generic everyday or discourse word with no specific technical meaning here ("approach", "case", "way", "example", "user" used generically).
- REJECT_WRONG_SENSE: the words are a technical term elsewhere, but in this sentence they are used in a non-technical sense.
- INSUFFICIENT_EVIDENCE: the sentence(s) shown do not let you decide.

Rules:
- Judge the span exactly as written. A longer or shorter span is not your concern, except that a phrase that merely wraps a shorter listed span with extra description is REJECT_NOT_CONCEPT.
- Co-selected spans are other spans kept for the same stretch. Two spans that are both independently meaningful ("TCP congestion control" and "congestion control") can both be ACCEPT_NEW.
- node_id is the id from EXISTING MATCHES for LINK_EXISTING and null otherwise.
- reason_code is one of: valid_technical_term, existing_node, generic_word, descriptive_phrase, value_or_example, discourse_phrase, wrong_sense, fragment_or_clause, unclear_context.
- One-word spans carry a TERM EVIDENCE entry. Evidence supports a verdict but never decides it.
- Return exactly one verdict per candidate_id, in the same order. When unsure between a concept and a non-concept, choose INSUFFICIENT_EVIDENCE rather than guessing ACCEPT_NEW.
